Apollo comp — not production

01 · idle

1px rule in --color-gray-on-noir (7.02:1 on noir). Value type is Newsreader at --font-body. Control height 53px at desktop, above the 44px touch minimum.

02 · hover

Rule lifts to --color-cotton. 180ms, --ease-out-sharp. Nothing moves.

03 · focus-visible

2px COTTON ring, 4px offset — NOT the global cherry ring, which is 1.19:1 against noir and would be close to invisible here. Rule doubles via box-shadow so nothing reflows.

04 · filled (blurred)

Rule stays cotton once the field holds a value, so a completed form reads as a column of solid rules and an incomplete one does not.

05 · invalid

Enter a valid email address.

Rule and its 1px shadow go to --color-accent-graphic (chili, graphic use on noir). Label goes to --color-accent-on-noir (chili-300, 4.97:1 — legal at 12px). Message sits below the control in chili-300 at 13px/500, wired by aria-describedby. Message text is validateInquiry()'s own string, verbatim.

06 · consent invalid

Consent is required to send this inquiry.

07 · consent checked

Checked box is a COTTON field with a noir mark — cherry is not spent here. Cherry appears as a solid field exactly once on the page.

08 · submit idle / hover / pending

Cherry field / cotton text, 9.03:1. Hover and active go to --color-accent-deep (maroon) — the depth step maroon exists for, and the only place it is allowed. Pending: maroon fill, cursor wait, a static cotton square, label "Sending". The square does not spin under prefers-reduced-motion.

09 · 422 VALIDATION_ERROR — status line

Check the highlighted fields and try again.

Server-returned errors are merged into the same per-field treatment as state 05. The status line sits directly above the actions row, role="alert", and focus moves to the first invalid control.
